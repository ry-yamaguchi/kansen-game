# 要望の受け取りと、継続的な消化

作者からの要望は**チャットに書かれるとは限らない**。`docs/backlog.md` に書き足されることがある。

#[[file:docs/backlog.md]]

## 守ること

1. **セッションを始めたら、まず `docs/backlog.md` を読む。** 未完了（`[ ]`）の項目を確かめ、
   「次はこれに着手します」と作者に提案してから動く。
2. **手が空いたら、勝手に終わりにせず backlog の次の項目へ進む。** 1つ終わるたびに
   backlog を見直す。作者が新しい行を足しているかもしれない。
3. **完了したら `[x]` に変え、「## 完了」へ日付つきで移す。** 変更はその作業のコミットに含める。
   終わっていないのにチェックを入れない。
4. **作業中に出た積み残し・気づいた要望は、その場で backlog に1行足す。**
   チャットの中だけに残すと失われる。
5. **作者の書き方は自由である。** 1行の走り書きでも、意図を確かめてから着手すること。
   曖昧なら勝手に解釈せず、短く質問する。

## 大きくなったら spec へ昇格させる

backlog の1行が「要件・設計を詰めないと作れない」大きさになったら、その行を spec
（`.kiro/specs/<名前>/`）に昇格させる。backlog 側の行は残し、「→ spec: <名前>」と追記して
どこへ行ったか分かるようにする。

小さい修正は spec を作らず、backlog から直接やってよい。**手続きを増やすことが目的ではない。**

## 置き場所の使い分け

| 置き場所                  | 入れるもの                                       |
| ------------------------- | ------------------------------------------------ |
| `.kiro/steering/`         | ずっと守ってほしい方針・前提（このファイル自身も） |
| `docs/backlog.md`         | やってほしいことの積み残し。作者が随時書き足す    |
| `.kiro/specs/<名前>/`     | 要件・設計を詰めて実装する、まとまった機能        |

## 自動化（`.kiro/hooks/backlog.json`）

- **SessionStart** — セッション開始時に backlog を読み、未完了の上位を提示する
- **PostTaskExecution** — spec のタスクが1つ終わるたびに backlog を更新する

`AgentStop`（応答のたび）は**あえて使っていない**。毎回エージェントを起こすと、
うるさいうえに終わりが見えなくなるためである。

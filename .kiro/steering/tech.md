# 技術スタックと制約

| 項目       | 採用                                      |
| ---------- | ----------------------------------------- |
| 言語       | TypeScript（strict を有効にする）         |
| ビルド     | Vite                                      |
| 描画       | Canvas 2D。UIフレームワークは使わない     |
| テスト     | Vitest                                    |
| 配信       | 静的ファイル（ホスティング先は未定）      |

依存は最小に保つ。ゲームエンジンや状態管理ライブラリを足す前に、まず素で書けないかを考える。
足すときは理由を docs/ に1行残す。

## 崩してはいけない設計

- **シミュレーション中核（`src/sim/`）は純粋関数だけで書く。** DOM・Canvas・`Date.now()`・
  `Math.random()` を呼ばない。時刻と乱数は引数で受け取る。描画を外してもヘッドレスで回る状態を保つ。
- **乱数はシード付きにする。** 同じシードと同じ操作列からは必ず同じ結果が出る（決定論）。
  これが崩れるとバランス調整もテストも成立しない。
- **バランス定数は `src/sim/balance.ts` に集める。** 数値をロジックに直書きしない。
- **止まっているときは資源を使わない。** 一時停止・タブ非表示・画面離脱で
  `requestAnimationFrame` のループとタイマーを確実に止める。放置で重くならないこと。

## コマンド

```bash
npm install
npm run dev     # 開発サーバ
npm test        # 合否は Tests の行で見る（tail で切らない）
npm run build
```

## テスト方針

- `src/sim/` はユニットテストで固定する。UI のテストは v1 では求めない。
- **決定論のテストは必須。** 同じシードで2回回して最終状態が一致すること。
- テストを書いたら**わざとロジックを壊して落ちるか**を確かめる。落ちないテストは無いのと同じである。
- 「勝てる」「負ける」の両方が成立することを、ヘッドレスで複数シードを回して確かめる。
